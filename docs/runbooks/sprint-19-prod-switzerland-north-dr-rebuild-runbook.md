## Purpose

Operationalize [ADR-0037](../adr/0037-prod-region-switzerland-north-greenfield.md)
as a repeatable, evidence-capturing runbook: **decommission the entire
eastus2/westus2 PROD footprint first (DR-style), then rebuild PROD greenfield in
`switzerlandnorth`** at SIT parity, in a single resource group `rg-ihzhhpf-prod`.

This is a **disaster-recovery-style rebuild in a new region**, not a resource
migration — all PROD data is synthetic and regenerated by the simulator, so
there is zero portable state (no Cosmos export/import, no PE rewire, no vector
re-index).

## Scope

### In scope

- **Phase 0** — DR-style decommission of the prior PROD footprint
  (`rg-ihzhhpf-prod-eastus2`, `fabricihzhhpfprod` in westus2, the managed App
  Insights RG, and the soft-deleted Foundry account).
- **Phase 1–8** — greenfield rebuild in `switzerlandnorth` at SIT parity,
  replaying the SIT-proven Option-1 flow (reuse `infra/main.bicep` via the new
  [`infra/environments/prod-swn.bicepparam`](../../infra/environments/prod-swn.bicepparam)).
- Verification and rollback for each phase; evidence capture.

### Out of scope

- **SIT** (westus2 + eastus2) — untouched by every step in this runbook. SIT
  resource groups (`rg-ihzhhpf-sit`) are excluded from every teardown command.
- PHI data onboarding and residency-tier (regional `Standard`) model
  deployment — deferred to a future PHI PROD per ADR-0037 (revisit criteria).
- Standing multi-region DR / failover — this is DR-*style* process, not a
  standing DR capability.
- Fabric IQ Ontology + Data Agent in PROD swn (Preview, per-capacity gate
  [#270](https://github.com/urruegg/SwissHospitalCapacityPlatform/issues/270)) —
  SIT remains the live Fabric IQ seam.

## Security and Compliance Guardrails

1. **SIT exclusion is mandatory.** Every teardown command targets a
   `*-prod*` resource explicitly. Before each `delete`, echo the target and
   assert it does not match `rg-ihzhhpf-sit`.
2. No secrets are echoed, logged, or committed; Key Vault names are recorded but
   never their contents.
3. Synthetic data only (ADR-0013 / ADR-0016) — no PHI is created, moved, or
   deleted; the region choice is topology/sovereignty readiness, not data
   residency.
4. Any deviation that cannot be remediated in-flight is recorded as a residual
   risk with an owner and expiry, not silently waived.


## Phase 2 — Foundation + AI + compute + data (baseline slice)

Single-region PROD reuses the SIT-proven orchestrator (`infra/main.bicep`,
Option 1) — no fresh module tree. The baseline slice deploys foundation
(identity + observability), AI platform (Foundry account), compute (agent-host +
app-fluent Container Apps + platform Cosmos), and the P4 data lane (Event Hubs,
Service Bus, CSA Cosmos).

### T2.0 — Create the single PROD RG

```bash
# ⚠️ approved-to-apply required
az group create --name rg-ihzhhpf-prod --location switzerlandnorth \
  --tags env=prod owner=platform-team costCenter=ihzhhpf-prod workload=hospital-capacity
```

### T2.1 — Stand up the PROD-local ACR + import images

The shared Container App module resolves the registry **by name in the
deployment RG**, so a PROD-local ACR is required (cross-RG/region pull is
unsupported):

```bash
# ⚠️ approved-to-apply required
az acr create -n crihzhhpfprod -g rg-ihzhhpf-prod --sku Basic -l switzerlandnorth
# Source registry = the SIT ACR cri75lbu5sj4hza (rg-ihzhhpf-sit, westus2)
az acr import -n crihzhhpfprod --source cri75lbu5sj4hza.azurecr.io/hcc-agent-host:b796961 \
  --image hcc-agent-host:b796961
az acr import -n crihzhhpfprod --source cri75lbu5sj4hza.azurecr.io/hcc-app-fluent:b796961 \
  --image hcc-app-fluent:b796961
```

### T2.2 — What-if, then deploy the baseline slice

```bash

  -g rg-ihzhhpf-prod -f infra/main.bicep \

az deployment group create -n sprint19-prod-swn-baseline \
```

## Phase 7 — DNS re-point + Entra (integration)

1. **DNS.** Re-point CNAME `app` in zone `curavias.ch` (rg-ihzhhpf-sit) from the
   old eastus2 PROD CA fqdn to the new **switzerlandnorth** app-fluent CA fqdn;

   single app registration `ihzhhpf-app` with the new swn CA fqdn; keep
   `https://app.curavias.ch`.

## Troubleshooting

- **Cross-RG ACR `ResourceNotFound`** — the Container App module resolves the
  registry by name in the deployment RG; always create a PROD-local
  `crihzhhpfprod` and `az acr import` (do not point at the SIT ACR).
- **Cosmos PE `InvalidPrivateDnsZoneIds`** — the `privatelink.documents.azure.com`
  zone is created only by the CSA-Cosmos module; keep `enableNetworkModule=false`
  for the baseline slice (network + PE is the hardening follow-up).
- **Foundry project `allowProjectManagement` BadRequest** — `PATCH` the account
  `properties.allowProjectManagement=true` before creating the project (#252).
