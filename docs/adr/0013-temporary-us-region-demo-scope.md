# ADR-0013 — Temporary US-region demo scope on new tenant

| Field | Value |
| ----- | ----- |
| **Status** | Accepted |
| **Date** | 2026-07-24 |
| **Author** | Urs Rüegg |
| **Supersedes (scoped)** | [ADR-0003](0003-swiss-regional-inference-for-phi.md) and [ADR-0004](0004-block-global-and-data-zone-for-phi.md) — **for the specific scope defined below only; both ADRs remain in force for all other environments and any future PHI deployment.** |

## Context

The 2026-07-01 AMA HCC & North Star review ([docs/reviews/2026-07-01-ama-hcc-northstar-review.md](../reviews/2026-07-01-ama-hcc-northstar-review.md)) identified a set of Azure and Fabric services (notably Fabric IQ Ontology and the operational-copilot integration paths) that are **preview or not yet GA in `switzerlandnorth`**. Blocking on Swiss regional GA would prevent the platform from prototyping and validating the North Star capabilities against the current "art of the possible" stack.

The new tenant `1337187a-4c41-4da9-8fca-731bba7a4329` (`MngEnvMCAP164444.onmicrosoft.com`) has been provisioned to host a **demonstration / proof-of-technology** environment for this validation. This environment will use **synthetic sample data only** — no PHI, no effective real patient data, no connection to any Swiss hospital data source.

[ADR-0003](0003-swiss-regional-inference-for-phi.md) mandates `switzerlandnorth` for **PHI**. [ADR-0004](0004-block-global-and-data-zone-for-phi.md) blocks global and US regions for **PHI**. Both ADRs are silent on non-PHI demo scope; this ADR closes that gap explicitly.

## Decision

For the **new-tenant demo scope only**, deploy Azure resources in **`westus2`** to unblock validation of services that are not yet GA in `switzerlandnorth`.

**Promoted Proposed→Accepted 2026-07-24** on OWNER confirmation (F3 synthetic-only US scope; F4 SIT cross-region access permitted).

SIT in `westus2` / `eastus2` is acceptable under the synthetic-only scope (F3), and cross-region access within the US SIT footprint is explicitly permitted because the data is synthetic (F4). This is a deliberate SIT↔PROD asymmetry: PROD in Switzerland North per [ADR-0037](0037-prod-greenfield-switzerland-north.md) is single-region with no cross-region hop, whereas SIT tolerates cross-region access for capability coverage.

Scope boundary (all four conditions must hold; violating any one auto-invalidates the exception):

1. **Tenant:** `1337187a-4c41-4da9-8fca-731bba7a4329` only. No other tenant is permitted to use `westus2` under this decision.
2. **Data:** **Synthetic data only**, generated by [`data/synthetic/generate_planning_datasets.py`](../../data/synthetic/generate_planning_datasets.py). No real patient identifiers, no direct or indirect connection to any Swiss KIS/hospital source, no import from the old-tenant environments.
3. **Purpose:** Demonstration and proof-of-technology validation of services not yet GA in `switzerlandnorth`. Not for production workload, not for regulated data.
4. **Duration:** Time-limited. Sunset when either (a) the required target services reach GA in `switzerlandnorth`, or (b) the exception expiry in `policy/exceptions.json` is reached — whichever comes first. Transfer of workload back to `switzerlandnorth` follows a separate migration decision.

Enforcement:

- Add a time-limited exception in [`policy/exceptions.json`](../../policy/exceptions.json) against `MC-RESIDENCY` per [ADR-0010](0010-policy-as-code-and-release-evidence-gates.md) (max 90-day validity, renewable via new review). Fields as required by `policy/exceptions.json.schema` — owner, approver, expiry, mitigation plan, follow-up validation date.
- Extend `@allowed` in `infra/modules/data-platform/fabric/main.bicep` and `infra/modules/data-platform/source-sql/main.bicep` to accept `westus2` in addition to `switzerlandnorth`, with an updated `@description` referencing this ADR.
- **Do not** remove `switzerlandnorth` from the residency allowlist in `policy/policy-pack.json` — the demo scope goes through the exception mechanism to preserve the audit trail.
- Environment parameter files (`infra/environments/sit.bicepparam`, `prod.bicepparam`) pin `location = 'westus2'` for the new tenant only; if a future non-demo Swiss environment is needed, it gets its own parameter file with `location = 'switzerlandnorth'`.

## Consequences

**Positive:**
- Unblocks validation of North Star services (Fabric IQ Ontology and adjacent paths) against the current GA/Preview mix.
- Preserves ADR-0003 and ADR-0004 as the default for any PHI/production scope — no silent weakening of the compliance baseline.
- Time-boxed via `policy/exceptions.json` mechanism; forces periodic review.

**Negative / risks:**
- Any accidental ingest of real PHI into the demo environment is a **critical incident** — synthetic-only rule must be enforced by data pipeline reviews.
- Migration back to `switzerlandnorth` will require the same runbook shape as this tenant migration.
- Cost of maintaining two operating regions (demo in US, target in Switzerland) accrues until sunset.

**Governance actions triggered by this ADR:**
- Add `docs/COMPLIANCE.md` addendum noting the demo-scope carve-out and pointer to this ADR.
- Update the tenant-migration spec, plan, runbook, and sprint report to reflect `westus2` for the demo scope.
- Add exception entry to `policy/exceptions.json` with 90-day expiry.
- Bump `.github/copilot-instructions.md` if it references `switzerlandnorth` as universally mandatory (it does not — no change needed there).
